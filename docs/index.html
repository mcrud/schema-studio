Build CRUD from a schema, not a terminal.

mcrud/schema-studio gives Laravel projects a browser-based schema builder that generates CRUD, translations, dashboards, roles and permissions.

View on GitHub

Schema Builder

Design multiple tables on a visual canvas, connect them with one-to-many, one-to-one or many-to-many relations, and set column types, nullable/unique rules and defaults.

Localized UI

Generate English and Arabic translation files with every CRUD resource.

Secure by default

Create action-level permissions and seed them into roles with Spatie Permission.

Install

composer require mcrud/schema-studio
php artisan vendor:publish --tag=crud-config
php artisan vendor:publish --provider="Spatie\Permission\PermissionServiceProvider" --tag="permission-migrations"
php artisan migrate

Laravel package discovery registers the package automatically. Open /crud-generator in your application to begin.

Design a schema

  1. Describe your project, or start from a template (Online Store, SaaS Workspace, Clinic, Restaurant).
  2. On the schema canvas, add tables such as Category and Product and define their columns. Drag ⋮⋮ to reorder columns.
  3. Drag the ● handle from one table onto another to create a relation: one to many, one to one or many to many. Foreign keys and pivot tables are created for you, and the Migration tab previews the code.
  4. Already have a database? Click Import from DB to bring existing tables, foreign keys and pivots onto the canvas, then add new columns or tables: new columns become an ALTER migration.
  5. Use undo/redo, zoom, pan and the minimap on larger schemas. Your draft is autosaved, and you can export the schema as JSON, the diagram as SVG/PNG, or copy a Mermaid ERD.
  6. Choose English and/or Arabic translations, the permissions to protect and roles such as admin, editor.
  7. Keep Run migrations & seed permissions and Create dashboard enabled, then generate.

What is generated?

Laravel code

For every table: migration, Eloquent model with relationships, resource controller, route registration and Blade index/form views. Many-to-many relations also get a pivot migration.

Authorization

A permission seeder per resource creates permissions and assigns them to the selected roles. Controllers protect each selected action.

Localization

Language files are placed in lang/en and/or lang/ar, and generated views use Laravel’s __() helper.

Relations

One to many

Adds parent_id (foreignId, constrained) to the child table, with hasMany and belongsTo methods.

One to one

Same as one to many, but the foreign key is unique and the parent uses hasOne.

Many to many

Creates a pivot table such as category_product and belongsToMany on both models.

Migrations are ordered so parent tables are created first. Circular one-to-many or one-to-one relations are rejected.

Migrate, seed & dashboard

With Run migrations & seed permissions enabled, the generator runs php artisan migrate --force (all pending migrations) and then every generated permission seeder. If a step fails, the files are kept and the message tells you what to run manually. To do it yourself:

php artisan migrate
php artisan db:seed --class=ProductPermissionSeeder

Create dashboard adds /dashboard with a count card linking to every generated table. It is skipped when a dashboard already exists.

Configuration & safety

Publish configuration with the install command above. In production, protect the builder itself by adding auth (and your admin middleware) to middleware in config/crud.php. Because the generator writes files and can run migrations, never expose it publicly. It never overwrites existing files: tables whose model, controller, view or migration already exist are skipped, so you can re-run it to add new tables.
